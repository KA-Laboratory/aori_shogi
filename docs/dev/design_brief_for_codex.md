## 1. 前提：このアプリは何か

将棋アプリ。対戦相手の AI が「自称・天才軍師」というキャラクターで、**プレイヤーを煽り、プレイヤーからも煽られる**。煽られると軍師の感情が動き、感情が動くと**指し手の質が実際に落ちる**。感情を揺さぶって勝ちをもぎ取るのがゲーム性。

- 思考エンジン: やねうら王 + Háo NNUE（本気で強い）
- セリフ生成: 端末内 LLM（Qwen3 1.7B を軍師口調に追加学習したもの、1.90GB）
- 実装: Flutter（Material 3）、**縦画面固定**、コンテンツ幅は `maxWidth: 520`
- 配布: Google Play / App Store を想定（個人開発）

### 1.1 技術的な制約（デザインが従うべき現実）

| 制約 | 値 | デザインへの影響 |
|---|---|---|
| 画面向き | 縦固定（`portraitUp`） | 横向きレイアウトは設計不要 |
| コンテンツ最大幅 | 520 dp | タブレットでも横に広がらない。中央寄せ |
| 想定最小幅 | 360 dp | ここで盤＋HUD が破綻しないこと |
| LLM 応答時間 | 中央値 4.6s / p95 5.9s（Galaxy S24） | **待ち時間を隠す演出が必須**。§4.6 |
| モデル未導入時 | 定型文で動く | 表情・HUD はモデル無しでも成立すること |
| 現在のテーマ種色 | `#8D5524`（木材の茶） | 変えてよい。変えるなら理由を書く |

### 1.2 ライセンス上の注意

本体は GPLv3（やねうら王・Háo 由来）。**画像・音声アセットは GPLv3 と共存できるライセンスで調達する前提**で仕様を書くこと。フォントも同様（Google Fonts の OFL なら可）。特定のフォントや素材を指定する場合はライセンス名を併記すること。

## 3. 成果物ごとの要求

### 3.1 `01-character.md` — 軍師のキャラクター設定書

**目的**: イラストレーターに渡して絵が描け、かつセリフの学習データを書くときの拠り所になる文書。

必ず含めること：

1. **一段落のログライン**（100字以内）。この人物を一言で。
2. **外見仕様**
   - 種別（人間／擬人化／人外）、年齢感、体格、頭身
   - 髪・目・肌の色を 16進で
   - 衣装（軍師なので甲冑・陣羽織・軍配などの語彙が想定されるが、和風縛りにする必要はない。決めて理由を書く）
   - **必ず持たせる識別子を3つ**（例: 軍配／片眼鏡／扇）。表情差分でも絶対に消えない要素として。シルエットで誰か分かること
3. **性格**
   - 芯にある動機（なぜ煽るのか、なぜ煽られると崩れるのか）
   - 自己認識と実像のギャップ（「天才」を自称するが抜けている、という設計）
   - **嫌われない線引き**：下品・人格攻撃・実在の属性いじりは不可。何が「かわいい失敗」で何が「不快」かの境界を例文で5対10示す
4. **口調**（既存の `assets/lines/gunshi_tone.json` と**矛盾しないこと**。以下は確定事項）
   - 一人称「私」、二人称「君」
   - 平静・ドヤ顔・取り繕い＝慇懃な紳士口調（「〜でございます」「〜ですな」）
   - 動揺＝敬語が崩れかけ
   - 大混乱＝完全に素（「〜のだ」「〜だぁ」、乱暴な言葉も可）
   - 禁止: 女性語（〜わね／〜かしら）、「あなた」「お前」「俺」「僕」
5. **代表セリフ 5気分 × 3本 = 15本**。口調プロファイルの実例として。
6. **やってはいけない表現**（NG リスト）。絵・文の両方。

### 3.2 `02-expressions.md` — 表情差分アセット仕様

**これが今回いちばん重要。イラストレーターへの発注書として単体で成立すること。**

#### 必須: 気分5種の割り当て

コード側の `Mood` enum は**これで固定**。増やさない。

| enum | 日本語ラベル | 発生条件（コード） | 求める表情の方向 |
|---|---|---|---|
| `composed` | 平静 | 初期状態・平常 | 余裕。丁寧だが見下している |
| `smug` | ドヤ顔 | 優勢 かつ 慢心 ≥ 0.5 | 高笑い。隙が生まれている |
| `rattled` | 動揺 | 焦り ≥ 0.45 または 冷静 < 0.45 | 取り繕えていない。汗 |
| `meltdown` | 大混乱 | 焦り ≥ 0.75 または（劣勢 かつ 冷静 < 0.3） | 崩壊。泣き言 |
| `coverUp` | 取り繕い | 直前の自分の手が 200cp 以上損した後 2手 | 誤魔化し。目が泳ぐ |

#### 決めること

1. **必要枚数**。上の5種が最低線。以下を追加するか判断し、**総枚数を確定**すること（イラスト外注費に直結するので「多いほど良い」は不可。**10枚以内**を目標とする）
   - 勝利／敗北の専用差分
   - 思考中（LLM 待ちの 4.6 秒に出るもの）
   - 交渉を持ちかけるときの専用差分
2. **キャンバス仕様**
   - 論理サイズ（dp）と書き出し倍率（1x/2x/3x）
   - アスペクト比、透過の有無
   - セーフエリア（円形にトリミングされても成立する範囲）
   - 形式（PNG / WebP）と**1枚あたりの上限 KB**（アプリサイズに効く。合計を明記）
3. **命名規則**。enum 名に機械的に対応させること。例: `assets/gunshi/face_composed.webp`。実装側が `Mood.name` から一意にパスを引けること。
4. **差分の作り方**。全身1枚絵 × N か、顔パーツ差し替えか。後者なら分割レイヤーの定義（目・眉・口・汗・頬）と組み合わせ表。
5. **ライト／ダーク**。両テーマで同じ画像を使うのか、輪郭の視認性のために背景処理を変えるのか。
6. **暫定運用**。イラストが上がるまでは現行の顔文字で動かす。**同じ差し替え口**（ファイル名／サイズ／配置）で後から画像に置き換えられるよう、暫定と本番の対応表を付けること。
7. **画像が無い／読み込み失敗のときの表示**。落ちないこと。

#### 表情遷移

- 気分が変わる瞬間のトランジション（クロスフェード何 ms か、揺れるのか）
- **同じ気分の中でも動きが欲しい**か（待機モーション）。やるなら手法とコストを書く
- 煽りが刺さった瞬間の**リアクション**（`TauntOutcome.composureDelta` が負に大きいとき）。表情とは別レイヤーの演出として定義

### 3.3 `03-visual-system.md` — ビジュアルシステム

1. **カラー**
   - シード色を決める（現行 `#8D5524`）。Material 3 の `ColorScheme.fromSeed` を使う前提
   - **ライト／ダーク両方**。ダークは「後で」ではなく今決める
   - 以下は現在ハードコードされている値。**体系の中に位置づけ直すこと**（そのままでも、変えてもよい。表で新旧対応を示す）

     | 用途 | 現行値 |
     |---|---|
     | mood: composed | `#5D7A8C` |
     | mood: smug | `#B8860B` |
     | mood: rattled | `#E67E22` |
     | mood: meltdown | `#C0392B` |
     | mood: coverUp | `#8E44AD` |
     | メーター: 冷静 | `#2E86C1` |
     | メーター: 慢心 | `#B8860B` |
     | メーター: 焦り | `#C0392B` |
     | メーター: 口軽 | `#8E44AD` |
     | メーター: 警戒 | `#34495E` |
     | 吹き出し: プレイヤー | `#E3F0FD` |
     | 吹き出し: 軍師 | `#FFF4E0` |
     | 提案行の背景 | `#FFF8D6` |

   - **コントラスト比 4.5:1 以上**を全テキストで満たすこと。満たさない組み合わせがあれば指摘して代替値を出す
   - 色だけに意味を持たせない（色覚特性への配慮）。形・ラベル・位置で冗長化する方法を書く
2. **タイポグラフィ**
   - 日本語フォント（ライセンス明記）。Material 3 の `TextTheme` のどのロールに何 sp を割るか表で
   - **駒の文字は別系統**（`piece_painter.dart` が描画）。ここは触らないが、UI 側と喧嘩しない指針を書く
   - 端末の文字サイズ設定を大きくした状態で崩れないこと（`textScaleFactor` 1.3 で検証する前提の指示を書く）
3. **スペーシング・角丸・影**
   - 4 または 8 の倍数系に統一。現行は 6/8/10/12 が混在している。**統一後の値と、既存の各箇所をどれに寄せるかの対応表**
4. **モーション**
   - 種類ごとの duration と curve（現行: メーター 500ms `easeOutBack`、表情の円 300ms）
   - 「アニメーションを減らす」OS 設定への対応方針

### 3.4 `04-hud.md` — 対局画面の HUD

**軍師の内面を、盤を邪魔せずに、一目で読ませる。**これが HUD の仕事。

#### 表示すべき情報（コードにあるもの。勝手に増やさない）

| 情報 | 型 | 現状の出し方 |
|---|---|---|
| 気分 | `Mood`（5値） | 顔文字＋ラベル |
| 形勢 | `Stance`（優勢/互角/劣勢） | テキスト |
| 冷静 `composure` | 0.0–1.0 | バー |
| 慢心 `hubris` | 0.0–1.0 | バー |
| 焦り `panic` | 0.0–1.0 | バー |
| 口軽 `looseLips` | 0.0–1.0 | バー |
| 警戒 `suspicion` | 0.0–1.0 | バー |
| 直前の煽りの効果 | `composureDelta` / `panicDelta` | 右端に `+12` 等 |
| 軍師のセリフ | 文字列 | 吹き出し |
| 思考中 | bool | `（ふむ……）` |
| 煽り可能残数 | bool（1手3回まで） | ヒント文 |
| 取引中の残り手数 | int | ヒント文 |
| 口が滑った | bool | 会話ログに `（口が滑った…？）` |
| 手番・王手 | — | 盤の下のテキスト |
| 持ち時間 | — | エンジンパネル |

#### 決めること

1. **5本のメーターは多すぎないか。** 常時5本出すのか、主要3本＋詳細は展開式か。**判断して理由を書く**。プレイヤーが「どれを動かせば勝てるか」を理解できることが最優先。
2. **メーターの見せ方**。バー／リング／アイコン＋数値。盤の上下どちらに置くか。
3. **差分（`+12` / `-25`）の演出**。煽りが刺さった手応えはこのゲームの快感の核心。数字が飛ぶのか、バーが弾けるのか。**刺さったとき／外したとき／逆効果だったときの3通り**を分けて定義（`mock` は慢心 > 0.6 で逆効果になる仕様がある）。
4. **形勢の表示**。将棋アプリ常連の評価値バーを出すか。**出すなら「軍師の自己申告」であって真実ではない**という建て付けにできないか検討すること（軍師はブラフをつく設定）。
5. **吹き出し**。セリフは最大 100 字程度。長文で盤が押し下げられないこと。溢れたときの扱いを決める。
6. **思考中の 4.6 秒**（§1.1）。ここを「待たされている」ではなく「軍師が唸っている」に見せる演出を設計する。既存は `（ふむ……）` の固定表示のみ。
7. **軍師の提案（交渉）**。以下の4種がモーダル的に割り込み、**答えるまで盤が固まる**。今は黄色い帯＋ボタン2個。割り込みの強さと、盤が固まっていることの伝え方を設計する。

   | enum | 文面 | 出る条件 |
   |---|---|---|
   | `offerPlayerUndo` | 一手待ってやろうか？ | 優勢・慢心 ≥ 0.55・直前にプレイヤーが損 |
   | `requestRedo` | すまん、さっきの置き直していいか？ | 直前の自分の手が 150cp 以上損 |
   | `proposeDeal` | 取引しないか？ 3手煽らなければ秘密の読み筋を教えよう | 互角・20手以降・焦り ≥ 0.25 |
   | `proposeDraw` | ここは引き分けということにしないか？ | 劣勢・焦り ≥ 0.6 |

8. **煽り入力**。定型スタンプ5種＋サンプル文6種＋自由入力。今は `ActionChip` が11個 `Wrap` で並んでいて雑然としている。整理案を出すこと。

   | id | kind | 文面 | 効果（冷静/慢心/焦り） |
   |---|---|---|---|
   | `blunder` | blunderCall | いまの手、悪手でしょ | −0.25 / — / +0.20 |
   | `hanging` | hangingPiece | 駒、浮いてない？ | −0.20 / — / +0.15 |
   | `threat` | threat | 玉、危なくない？ | −0.10 / — / +0.30 |
   | `mock` | mock | 天才軍師（笑） | −0.15 / — / +0.05 |
   | `praise` | praise | さすが天才軍師さま！ | +0.10 / +0.10 / — |

   ※ `praise` は軍師を**回復させる**が、慢心を上げて隙を作る。この二面性が伝わる見せ方にすること。

### 3.5 `05-screens.md` — 画面構成と設定

#### (A) 対局画面の再設計

現状 1 画面に 9 ブロック縦積み。**盤が常に見えていること**を絶対条件に、構成を決め直す。検討軸：

- 盤を固定し、HUD と会話欄をシート／タブに逃がすか
- 会話欄（高さ 160dp のログ＋入力欄）の置き場所
- エンジン設定（対局相手・持ち時間・強さ）を設定画面へ移すか
- 手番・王手の表示位置
- 「待った」「投了」「新規対局」の3ボタンの置き場所

**制約**: 提案が出ている間は指せない。その理由が**必ず盤の近くで見えること**（過去に画面外に出て「固まった」と誤解されたバグの再発防止）。

#### (B) 設定画面（新規。今は存在しない）

将棋アプリ／一般的なゲームにある設定を**網羅的に洗い出し、採否を判断し、階層に整理**すること。最低限このへんは検討対象：

- 対局: 対局相手（人間同士／AI先手／AI後手）、AI の強さ（入門・やさしい・ふつう・強い・全力）、持ち時間、成り確認ダイアログの要否、投了確認
- 軍師: 煽りの頻度、セリフの長さ、LLM を使う／定型文のみ、モデルの導入と削除、軍師が覚えていることの閲覧・消去
- 表示: テーマ（ライト／ダーク／端末に従う）、盤と駒の意匠、座標表示、最終手ハイライト、利きの表示、文字サイズ
- 音: BGM 音量、効果音音量、軍師のボイス（将来）、触覚フィードバック
- データ: 棋譜の保存・書き出し（KIF）、対局履歴、統計、全データ削除
- その他: ライセンス（GPLv3 / 第三者通知）、プライバシー、バージョン、問い合わせ

各項目について **既定値**と、**設定が対局中に変わったときの挙動**を決めること。

#### (C) 初回起動

現状なし。必要か判断する。必要なら：

- 軍師の自己紹介（キャラ導入）
- 「煽ると相手が弱くなる」という**このゲームの核を必ず伝える**
- 1.90GB のモデルをいつ・どう勧めるか（Wi-Fi 推奨、無くても遊べる）
- 何画面で終わらせるか（多すぎると離脱する）

#### (D) 終局

勝敗表示、軍師の敗北／勝利セリフ、感想戦への導線、再戦。今は `AlertDialog` すら無く手番表示が結果ラベルに変わるだけ。

#### (E) 画面遷移図

### 3.6 `06-feedback.md` — 音・触覚・演出

**トリガ表**を作る。列は「イベント → 音 → 触覚 → 画面演出 → 優先度」。イベントは最低限これら：

駒を持つ／置く／取る／成る／王手／詰み／投了／煽りが刺さった／煽りが外れた／煽りが逆効果／軍師が口を滑らせた／軍師が提案してきた／提案を受けた・断った／気分が変わった／軍師が長考に入った／対局開始／勝利／敗北

- 音は**尺（ms）と質感**を言葉で指定すること（実ファイルは後で調達）。合計ファイルサイズの目標も。
- 触覚は Flutter の `HapticFeedback`（light/medium/heavy/selection）のどれに対応させるか。
- **無音で遊んでも情報が欠けないこと**。音だけで伝える情報を作らない。
