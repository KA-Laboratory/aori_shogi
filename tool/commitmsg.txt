モデルのダウンロードを検証してから入れる（実機で確認済み）

これまでの install() は flutter_gemma の fromNetwork() 任せで、落ちてきた 1.9GB が
正しいか誰も見ていなかった。途中で切れてもモデルは読み込めてしまい、壊れた日本語を
喋る（int4 を試したときに、まさにその壊れ方を見た）。そうなると「モデルが悪い」と
誤診して原因を延々と探すことになる。

ModelDownloader を入れた。型は NnueStore.download() と同じで、.part に落とす →
サイズ照合 → sha256 照合 → rename。通ったものだけ installFromFile() に渡し、
入れ終わったら複製を消して容量を返す。

LlmModelSpec に sha256 を足した。自前で配るものには必ず入れる。他所のモデルは
ハッシュが公表されていないので null（サイズだけ見る）。

model_catalog.dart に gunshiFinetuned（軍師の学習済みモデル）を足した。
サイズ 1900934064 と sha256 は入っていて、url だけが空。R2 の URL が決まれば
一覧に出て、そのまま取得できる。url が空の間は一覧に出さない。

URL が無くても実機で試せた。adb reverse tcp:8000 tcp:8000 で PC の HTTP サーバーを
端末から見えるようにして、本物の 1.9GB を配った。
- 正常系: 取得 → 検証 → 導入まで通り「端末内のモデルで喋ります。」になった。
- 異常系: 末尾 5000 バイトを削ったファイルを配ると端末で弾いた。
  「大きさが合いません（1900929064 / 1900934064 バイト）。通信が途中で切れた
  可能性があります」。しかも既に入っているモデルは壊れない。

単体テストは本物の HttpServer を立てて、途中切れ・ハッシュ不一致・404・.part の
後始末・進捗・再取得の省略を見ている。テストは 111件通過。
